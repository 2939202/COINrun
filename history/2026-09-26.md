## 1. 장비 세트 시스템 추가

**왜 이걸 먼저 했나**

달려서 골드를 모으는데 쓸 곳이 없었어요. `잡화점` 버튼은 `onTap: () {}`(빈 함수)였고, 장비는 `equipment` 문자열 한 개였어요.
골드 소비처가 생겨야 "달린다 → 보상 → 강해진다 → 또 달린다"가 닫힙니다.

**정한 방식**

장비는 투구/갑옷/무기를 따로 사는 게 아니라 **세트 한 벌을 통째로** 사고 입습니다. 등급 개념은 두지 않았어요.
그래서 유저가 입고 있는 장비는 항상 세트 하나(또는 맨몸)뿐입니다.

| 세트 | 가격 | 요구 레벨 | 힘 | 체력 | 속도 |
|---|---|---|---|---|---|
| 초급 모험가 세트 | 500 G | 1 | 3 | 3 | 2 |
| 중급 모험가 세트 | 3,000 G | 5 | 8 | 8 | 5 |
| 고급 모험가 세트 | 12,000 G | 10 | 15 | 15 | 10 |

능력치가 표시만 되면 살 이유가 없어서 실제 보상에 연결했어요.

- **힘** → 골드를 그 수치(%)만큼 더 받음
- **체력** → 경험치를 그 수치(%)만큼 더 받음
- **속도** → 아직 쓰는 곳 없음 (자리만 잡아둠)

(처음에는 力·氣·速 한자로 만들었는데, UI 컨셉이 정해지기 전이라 한글로 되돌렸습니다.)

가격은 지금 수급량에 맞췄어요. 10걸음당 1G라서 5km 러닝 한 번이 약 600G입니다.
초급은 첫 러닝으로, 중급은 누적 25km쯤, 고급은 누적 100km쯤에 손에 들어옵니다.
요구 레벨도 그 시점의 누적 러닝 시간과 맞아떨어지게 뒀어요. (골드와 레벨 중 한쪽만 먼저 차면 기다리도록 일부러 비슷하게 맞춤)

**파일**

| 파일 | 내용 |
|---|---|
| `lib/models/equipment_set.dart` (새) | 세트 한 벌의 정보 |
| `lib/game/equipment_catalog.dart` (새) | 세트 3종 목록. 나중에 Firestore로 옮겨도 이 파일 안에서 끝남 |
| `lib/game/equipment_rules.dart` (새) | 구매 가능 판정(`PurchaseCheck`), 보너스 계산, 장착 세트 이름 |
| `lib/screens/shop_screen.dart` (새) | 잡화점. **뼈대만** — 동작은 다 되지만 모양은 시안 확정 후 다시 만듦 |
| `lib/models/user_model.dart` | `equipment` 문자열 → `ownedSetIds` 목록 + `equippedSetId` |
| `lib/game/run_rules.dart` | `expFor`/`goldFor`에 `gear` 인자 추가 (장비 보너스 반영) |
| `lib/services/user_repository.dart` | `buySet`/`equipSet` 트랜잭션 추가, `saveRun`이 장비 보너스 반영 |
| `lib/screens/profile_screen.dart` | 잡화점 버튼 연결, 입은 세트·다음 노릴 세트 실제 값 표시 |
| `lib/screens/run_screen.dart` | 러닝 중 보상 미리보기도 장비 보너스 반영 (완료 리포트와 숫자가 어긋나지 않게) |
| `test/equipment_rules_test.dart` (새) | 구매 판정·보너스·저장 테스트 16개 |

**주의해서 만든 곳**

- 구매/장착은 **트랜잭션**이에요. 버튼을 빠르게 두 번 눌러도 골드가 두 번 빠지지 않습니다.
- `equippedSetId`에 목록에 없는 id가 저장돼 있어도 앱이 죽지 않고 맨몸으로 봅니다. (세트를 나중에 지워도 안전)
- 장비를 붙이기 전에 만든 Firestore 문서는 `ownedSetIds`가 없어서 빈 목록으로 읽힙니다. 기존 테스트 유저는 맨몸 상태로 이어집니다.
- Firestore에 남아 있는 옛 `equipment` 필드는 이제 아무도 읽지 않아요. 지워도 되고 그냥 둬도 됩니다.
- 러닝 기록(`runs`)에 `gearSetId`를 같이 남깁니다. 나중에 기록 화면에서 쓸 수 있어요.

## 2. 로그인 기능 추가

**왜 지금 했나**

`user_test_01`이 코드에 박혀 있어서 모든 기기가 같은 계정을 봤어요. 계정이 생겨야 골드와 레벨이 "내 것"이 됩니다.

**정한 방식**

Google 로그인은 뺐습니다. `android/app/google-services.json`의 `oauth_client`가 비어 있어서(SHA-1 미등록) 지금 붙이면 실행 중에 실패합니다. 콘솔 설정이 끝난 뒤에 붙이는 게 맞다고 봤어요.

대신 **게스트 + 이메일** 두 가지로 했습니다.

| 방법 | 설명 |
|---|---|
| 게스트 (익명) | 이메일 없이 바로 시작. 앱을 껐다 켜도 이어짐. 앱을 지우거나 폰을 바꾸면 사라짐 |
| 이메일 | 어디서든 같은 기록으로 들어옴 |
| 게스트 → 이메일 연결 | `linkWithCredential`을 써서 **uid를 그대로 두고** 이메일만 붙임. 골드·레벨·기록이 전부 유지됨 |

세 번째가 핵심이에요. 게스트로 놀다가 새로 가입해 버리면 uid가 바뀌어서 그동안의 기록을 잃는데, 연결 방식은 같은 계정에 이메일만 얹는 거라 안 잃습니다.

**파일**

| 파일 | 내용 |
|---|---|
| `lib/services/auth_service.dart` (새) | 로그인/가입/연결/로그아웃. Firebase 영어 오류 코드를 한국어 문장으로 바꿔서 던짐 |
| `lib/screens/login_screen.dart` (새) | 로그인·회원가입·계정연결 세 가지를 `AuthMode`로 처리 |
| `lib/screens/auth_gate.dart` (새) | 로그인 상태를 보고 로그인 화면 / 홈 화면을 고름. 첫 로그인이면 유저 문서를 만들어 둠 |
| `firestore.rules` (새) | 보안 규칙. **아직 적용 안 됨** — 콘솔에 붙여넣어야 함 |
| `lib/main.dart` | `home`이 `MainScreen` → `AuthGate` |
| `lib/screens/main_screen.dart` | `testUserId` 제거하고 로그인한 uid를 받음. 임시 환영 화면 삭제 |
| `lib/services/user_repository.dart` | `createUser` → `ensureUser`(있으면 손대지 않음), `updateNickname` 추가 |
| `lib/screens/settings_screen.dart` | 계정 섹션을 실제로 동작하게: 닉네임 변경 / 계정 저장하기 / 로그아웃 |
| `test/auth_test.dart` (새) | 기본 닉네임 짓기 테스트 |

**주의해서 만든 곳**

- `ensureUser`는 문서가 **없을 때만** 만듭니다. 예전 `createUser`처럼 `set()`으로 덮어쓰면 로그인할 때마다 골드가 0으로 돌아갑니다.
- 닉네임은 자동으로 지어집니다. 이메일이면 `@` 앞부분, 게스트면 `러너` + uid 앞 4글자. 설정에서 바꿀 수 있습니다.
- 게스트 로그아웃은 되돌릴 수 없어서, 확인 창에서 기록이 사라진다고 미리 알려줍니다.
- 첫 로그인 때 인터넷이 끊겨 유저 문서를 못 만들면 "다시 시도" 화면을 보여줍니다. (그냥 두면 빈 화면에서 멈춤)

**해야 할 설정 (콘솔 작업)**

1. Firebase 콘솔 > Authentication > Sign-in method 에서 **익명**과 **이메일/비밀번호** 켜기
   - 안 켜면 `operation-not-allowed` 오류가 납니다. 이 경우 화면에 무엇을 켜야 하는지 한국어로 나옵니다.
2. Firebase 콘솔 > Firestore Database > 규칙 에 `firestore.rules` 내용 붙여넣고 게시
   - 지금은 규칙이 없어서 남의 골드를 읽고 고칠 수 있는 상태입니다.

**알아두실 점**

기존 테스트 데이터(`users/user_test_01`)는 Firestore에 그대로 남아 있지만 이제 아무도 읽지 않습니다. 로그인하면 새 계정으로 Lv.1 · 0골드부터 시작합니다. 지워도 됩니다.

**확인 결과**

- `flutter test`: 30개 모두 통과
- `flutter build apk --debug`: 성공
